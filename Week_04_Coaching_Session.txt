========================================================================

**Question:** Thinking about the validation flow, what happens step by step in your application when a user submits a new category name like `AB`, starting from the POST request and ending when the validation error appears to the user?

========================================================================

USER (Joshua Jimenez Peralta):
When a user submits AB as a category name, the validation chain in categoryValidation middleware runs first trim() removes whitespace, notEmpty() passes, but isLength({ min: 3, max: 100 }) fails because "AB" is only 2 characters, so the error message gets queued. Inside the controller, validationResult(req) captures those errors, !errors.isEmpty() evaluates to true, and the forEach loop calls req.flash('error', error.msg) for each validation failure, storing the message in the session. The controller then redirects back to the form page with res.redirect(), and when that GET request arrives, the flash middleware retrieves that error message from the session and makes it available to the view. The EJS template renders the form again, displaying the error message (probably in an alert or error box) to the user, and then that flash message is automatically cleared from the session so it won't appear on subsequent page visits all because the session persisted that error message across the redirect.
